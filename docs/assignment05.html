Data

I used mtcars, one of R’s sample datasets: 32 cars tested by Motor Trend magazine in 1974. The charts use fuel consumption (mpg), weight (wt) and number of cylinders (cyl).

Part 1. Base graphics

My style

Code 
windowsFonts(Garamond = windowsFont("Garamond"))

cores <- c("steelblue", "forestgreen", "firebrick")

fonte <- "Data source: Motor Trend (1974), R dataset mtcars."

meu_estilo <- function() {
  par(family = "Garamond", las = 1, bty = "l", mar = c(6, 5, 4, 2),
      col.main = "darkblue", col.lab = "gray30", col.axis = "gray30",
      cex.main = 1.3, lwd = 2)
}

My theme

library(tidyverse)

theme_mine <- function() {
  theme_classic(base_size = 13, base_family = "Garamond") +
    theme(plot.title = element_text(colour = "darkblue", face = "bold", hjust = 0.5),
          axis.title = element_text(colour = "gray30"),
          axis.text = element_text(colour = "gray30"),
          plot.caption = element_text(colour = "gray40", hjust = 0))
}

Which system was easier?

Histogram. Base R was easier. hist() chose the bins and the axis marks by itself.

Bar chart. ggplot2 was a little easier. The legend came automatically.

Pie chart. Base R was much easier. pie() draws the chart in one command.

Boxplot. Both were about the same.

Scatterplot. ggplot2 was easier. In base R I had to pick the color and symbol of each point and write the legend myself.

Part 3. Output formats

I exported the scatterplot from Part 1 (base R) and from Part 2 (ggplot2) at 6.5 × 4 inches, in six formats. Raster formats use 300 dpi. For the PDF I used cairo_pdf(), the version of pdf() that accepts Windows fonts such as Garamond.

Code 
grafico_base <- function() {
  op <- meu_estilo()
  grupo <- as.factor(mtcars$cyl)
  plot(mtcars$wt, mtcars$mpg, col = cores[grupo], pch = c(16, 17, 15)[grupo], cex = 1.4,
       main = "Heavier cars use more fuel",
       xlab = "Weight (1,000 lbs)", ylab = "Miles per gallon (mpg)")
  abline(lm(mpg ~ wt, data = mtcars), lty = 2, col = "gray40")
  legend("topright", legend = c("4 cylinders", "6 cylinders", "8 cylinders"),
         col = cores, pch = c(16, 17, 15), bty = "n")
  mtext(fonte, side = 1, line = 4.5, adj = 0, cex = 0.8, col = "gray40")
  par(op)
}

Zoom to 400%. PDF and SVG files - text and lines smooth and sharp. PNG, TIFF and BMP files, the edges of letters, symbols and the dashed line showed small steps (pixels). JPG file, edges blurry. TIFF and BMP looked like PNG.

Which format for which destination:

  • Journal article: PDF. It is small, stays sharp at any size and in print, and keeps the fonts.
  • Web page: PNG (or SVG). PNG is small, sharp, lossless and supports transparency; SVG also.
  • PowerPoint slide: PNG. It opens in any version of PowerPoint.

Reflection

Cleveland and McGill tested how accurately people read different visual elements. From most to least accurate:

  • position along a common scale (points or bars aligned on the same axis);
  • length (the size of a bar);
  • angle and slope;
  • area;
  • volume and color.

A pie chart forces the reader to compare angles and areas, which rank 3rd and 4th. Bars use length from a common baseline, which ranks 1st and 2nd. This is why pie charts are often criticized. My own charts show the problem. In the pie chart, the slices for 4 cylinders (34%) and 8 cylinders (44%) look close in size.
